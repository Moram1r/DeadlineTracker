# Спецификация проекта: Отслеживатель дедлайнов (MVP v2)

## Кратко
Мини‑сайт для личного учета дедлайнов. Пользователь добавляет запись с датой, текстом и настраиваемым тегом «размера/сложности». Список выводится с двумя режимами сортировки: по дате и по тегу (по приоритету тега). Можно отмечать задачи выполненными — они скрываются из активного списка и доступны в отдельном представлении с возможностью восстановления. Запись можно редактировать.

Стек MVP: статическая клиентская страница (HTML/CSS/JS), данные хранятся в LocalStorage. Без регистрации и бэкенда.

## Цели
- Быстро фиксировать дедлайны и видеть ближайшие.
- Переключаться между сортировками: по дате и по тегу (приоритет).
- Управлять статусом задачи: активная/выполненная, с возможностью восстановления.
- Редактировать существующие записи.

## Термины
- Дедлайн (задача) — запись с полями: текст, дата, тег (ссылка на сущность Tag), статус.
- Тег (Tag) — настраиваемая сущность с именем и числовым приоритетом, влияющим на сортировку по тегу.

## Объем MVP
Входит:
- Добавление дедлайна: текст, дата, выбор тега (обязательные).
- Просмотр активных дедлайнов, отдельное представление выполненных.
- Переключение сортировки: «по дате» и «по тегу (приоритет)».
- Отметка «выполнено» и «восстановить».
- Редактирование записи (текст, дата, тег, статус).
- Управление тегами: добавление, переименование, изменение приоритета; удаление — только если тег не используется.
- Сохранение данных в LocalStorage, хранение выбранных режимов.

Не входит (позже):
- Уведомления/напоминания.
- Множественные теги на задачу.
- Фильтры/поиск.
- Многопользовательский режим и синхронизация.

## Пользовательские сценарии
1) Добавление: заполнить текст, дату, выбрать тег → Добавить → задача появляется в активном списке.
2) Сортировка: переключить селект «По дате»/«По тегу» — порядок элементов меняется.
3) Завершение: нажать «Готово» → задача исчезает из активного списка, появляется в списке «Завершенные».
4) Восстановление: в списке «Завершенные» нажать «Восстановить» → задача возвращается в активные.
5) Редактирование: нажать «Редактировать» → изменить поля → Сохранить.
6) Управление тегами: открыть «Теги», добавить новый тег (имя, приоритет); при необходимости поменять приоритеты; удалить тег, если он нигде не используется.
7) Перезагрузка страницы сохраняет задачи, теги, выбранный режим сортировки и выбранное представление (Активные/Завершенные).

## Требования

### Функциональные
1. Форма добавления задачи
   - Поля:
     - Текст (1–200 символов, обязательное).
     - Дата дедлайна (YYYY-MM-DD, обязательное).
     - Тег (выбор из доступных тегов, обязательное).
   - Валидации: текст не пустой; дата корректна; выбран существующий тег.
   - При успехе форма очищается.

2. Список задач и представления
   - Два представления: «Активные» (default) и «Завершенные» (переключатель/табы).
   - Элемент списка показывает: текст, дату (локализовано), название тега, статусные действия.
   - В «Активных»: действия «Готово», «Редактировать».
   - В «Завершенных»: действия «Восстановить», «Редактировать».
   - Просроченные (dueDate < сегодня) выделяются визуально во всех представлениях.

3. Режимы сортировки
   - По умолчанию: «по дате».
   - «По дате»: dueDate ASC; при равенстве — createdAt ASC.
   - «По тегу (возр.)»: по приоритету тега ASC; внутри одного тега — dueDate ASC; далее createdAt ASC.
   - «По тегу (убыв.)»: по приоритету тега DESC; внутри одного тега — dueDate ASC; далее createdAt ASC.
   - Режим сортировки хранится и восстанавливается (LocalStorage).

4. Статусы задач
   - status: active | completed.
   - Пометка «Готово» устанавливает status=completed и completedAt=now (UTC).
   - «Восстановить» устанавливает status=active и completedAt=null.

5. Редактирование задачи
   - Доступно в обоих представлениях.
   - Разрешено менять: text, dueDate, tagId; опционально статус (переключателем), либо отдельные кнопки «Готово»/«Восстановить».
   - updatedAt обновляется при каждом сохранении.

6. Управление тегами
   - Список тегов: name (уникален в рамках клиента), priority (целое число, по умолчанию 100), optional color (строка CSS, необязательно для MVP-показа).
   - Операции: добавить (name обязательное), переименовать, изменить priority.
   - Удаление разрешено, только если ни одна задача не ссылается на этот тег; иначе — запрет с подсказкой «Тег используется N задачами».
   - При отсутствии тегов — требуется создать хотя бы один тег перед добавлением задач.

7. Сохранение данных (LocalStorage)
   - Ключи:
     - deadlineTracker.v2.tasks — массив задач.
     - deadlineTracker.v2.tags — массив тегов.
     - deadlineTracker.sortMode — 'date' | 'tagAsc' | 'tagDesc'.
     - deadlineTracker.viewMode — 'active' | 'completed'.

8. Миграция с v1
   - Если найдено deadlineTracker.v1 (массив задач старого формата), но нет v2:
     - Создать начальные теги: Small (priority 0), Big (priority 1); опционально добавить Medium (priority 1), сдвинув Big до 2. В UI их показать как «маленькое», «среднее», «большое».
     - Сопоставить старое поле size ('small'|'big') к соответствующим tagId.
     - Проставить status='active', completedAt=null.
     - Сохранить в v2-структуру и удалить v1-ключ.

### Нефункциональные
- Производительность: список до ~1000 элементов без заметных лагов.
- Браузеры: последние версии Chrome/Firefox/Edge; мобильные — по возможности.
- Доступность: элементы управляемы с клавиатуры; aria-метки для действий.
- Локализация: русский по умолчанию, формат дат — RU.

## Модель данных
Сущность Task (задача):
```
{
  id: string,            // uuid v4 или ULID
  text: string,          // 1–200 символов
  dueDate: string,       // YYYY-MM-DD (локальная дата без времени)
  tagId: string,         // ссылка на Tag.id
  status: 'active'|'completed',
  completedAt: string|null, // ISO дата-время (UTC) или null
  createdAt: string,     // ISO дата-время (UTC)
  updatedAt: string      // ISO дата-время (UTC)
}
```

Сущность Tag:
```
{
  id: string,            // uuid v4 или ULID
  name: string,          // уникально (регистрочувствительность по усмотрению)
  priority: number,      // чем меньше — тем «раньше» в сортировке по тегу
  color?: string         // optional, CSS-цвет для бейджа
}
```

Пример LocalStorage:
```
// deadlineTracker.v2.tags
[
  {"id":"t1","name":"маленькое","priority":0},
  {"id":"t2","name":"среднее","priority":1},
  {"id":"t3","name":"большое","priority":2}
]

// deadlineTracker.v2.tasks
[
  {
    "id":"01JABCD123",
    "text":"Сдать лабу по ОП",
    "dueDate":"2026-12-01",
    "tagId":"t1",
    "status":"active",
    "completedAt":null,
    "createdAt":"2026-11-18T10:22:00Z",
    "updatedAt":"2026-11-18T10:22:00Z"
  }
]
```

## Сортировка (алгоритмы)
- По дате:
  1) a.dueDate vs b.dueDate (ASC)
  2) a.createdAt vs b.createdAt (ASC)

- По тегу (возр.):
  1) tagPriority[a.tagId] vs tagPriority[b.tagId] (ASC)
  2) a.dueDate vs b.dueDate (ASC)
  3) a.createdAt vs b.createdAt (ASC)

- По тегу (убыв.):
  1) tagPriority[a.tagId] vs tagPriority[b.tagId] (DESC)
  2) a.dueDate vs b.dueDate (ASC)
  3) a.createdAt vs b.createdAt (ASC)

## UI (MVP)
- Верхняя панель: заголовок «Дедлайны», селект сортировки («По дате», «По тегу»), переключатель представления («Активные» / «Завершенные»), кнопка «Теги».
- Форма добавления (видна в «Активных»):
  - Текст: input[type=text] (или textarea до 3 строк).
  - Дата: input[type=date].
  - Тег: select из списка тегов.
  - Кнопка «Добавить» (disabled при невалидных данных).
- Список задач:
  - Карточка/строка: Текст • Дата (ДД.ММ.ГГГГ) • Бейдж тега • Кнопки действий.
  - Активные: «Готово», «Редактировать».
  - Завершенные: «Восстановить», «Редактировать», дата завершения (мелким шрифтом).
  - Пустые состояния: «Нет активных задач» / «Нет завершенных задач».
- Управление тегами (модалка/страница):
  - Таблица: Имя | Приоритет | Действия (Редактировать, Удалить).
  - Кнопка «Добавить тег» (Имя, Приоритет, Цвет [опц.]).
  - Подсказка при попытке удалить используемый тег.

## Техническая архитектура (клиент‑only)
- Файлы:
  - index.html — разметка, контейнеры.
  - styles.css — стили.
  - src/app.js — инициализация, роутинг представлений (активные/завершенные), обработчики.
  - src/storage.js — LocalStorage, миграции (v1→v2), версия схемы.
  - src/model.js — фабрики/валидации Task и Tag.
  - src/sort.js — функции сортировки.
  - src/tags.js — управление тегами (CRUD, проверка использования, изменение приоритета).
  - src/ui/*.js — компоненты (список, форма, модалка тегов), опционально.

- Даты хранить в ISO; dueDate без времени (локальная дата), timestamp’ы — UTC.
- Ключи LocalStorage и версия схемы должны быть константами в одном месте.

## Валидации и ошибки
- Текст обязателен, длина ≤ 200.
- Дата обязательна, корректная; просроченность — не блокер, только визуальная пометка.
- Тег обязателен, ссылка должна указывать на существующий Tag.
- Имя тега — непустое и уникальное (case-insensitive — по решению, рекомендовано).
- Приоритет тега — целое число в разумных пределах (например, −1e6…1e6).
- Удаление тега, если он используется, запрещено с сообщением с количеством привязанных задач.

## Тестовые случаи (MVP v2)
1) Добавление валидной задачи → появляется в активных, сохраняется в v2.
2) Сортировка по дате → ближайшие сверху; стабильность по createdAt.
3) Сортировка по тегу (возр.) → порядок по priority ASC; внутри — по дате.
3.1) Сортировка по тегу (убыв.) → порядок по priority DESC; внутри — по дате.
4) Пометка «Готово» → задача исчезает из «Активных», видна в «Завершенных», проставлен completedAt.
5) «Восстановить» → задача возвращается в «Активные», completedAt=null.
6) Редактирование текста/даты/тега → изменения видны, updatedAt меняется.
7) Управление тегами: добавление, изменение приоритета отражается в сортировке; удаление запрещено, если тег используется.
8) Миграция v1→v2: старые записи корректно конвертируются, сортировка по тегу работает на новых тегах.
9) Сохранение режима сортировки и выбранного представления между сессиями.

## Возможные расширения
- Множественные теги на задачу и фильтры по тегам.
- Архив (отдельно от «выполнено»), повторяющиеся задачи, шаблоны.
- Уведомления (браузерные/бот), дедлайны с временем.
- Экспорт/импорт JSON, синхронизация/бэкенд, PWA.

## Допущения
- Однопользовательское локальное приложение.
- Минимум UI-сложности: управление тегами — простая форма, изменение приоритета числом (без drag&drop в MVP).
- Язык интерфейса — русский.
